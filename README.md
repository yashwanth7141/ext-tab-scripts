# External Table Creation Script

A Python-based utility for creating PostgreSQL Foreign Tables from Parquet files using `parquet_fdw`.

The script is designed to process Parquet data generated by IBM Optim Archive Viewer and create the corresponding PostgreSQL schemas and Foreign Tables automatically.

## Features

* Creates PostgreSQL schemas automatically.
* Discovers one or multiple schema directories from the provided destination path.
* Discovers Parquet table directories automatically.
* Supports tables containing one or multiple Parquet files.
* Creates PostgreSQL Foreign Tables using `parquet_fdw`.
* Supports replacing existing Foreign Tables.
* Preserves schema and table name case using quoted PostgreSQL identifiers.
* Optionally verifies the row count of created Foreign Tables.
* Generates a processing report.
* Maintains separate information and error logs.
* Uses a single PySpark session during the complete execution.

## Requirements

* Python 3.12.x
* PostgreSQL 16.4 or higher
* `parquet_fdw`
* Java 11 
* Required Python packages listed in `requirements.txt`

## Installation

Clone the repository:

```bash
git clone https://github.com/yashwanth7141/ext-tab-scripts.git
cd ext-tab-scripts
```

Create and activate a virtual environment:

```bash
python3.12 -m venv ext_tab_venv
source ext_tab_venv/bin/activate
```

Install the required Python packages:

```bash
pip install -r requirements.txt
```

## Configuration

The script uses `config.json` for configuration.

Run the below comamnd to generate `config.json` file :

```bash
python config_installer.py
```

The configuration contains items such as:

* PostgreSQL connection details
* Foreign Server name
* SQL commands
* PostgreSQL datatype mappings
* Foreign Table creation options
* Row-count verification settings

### Foreign Table Options

Example:

```json
"table_creation": {
    "replace_existing": true,
    "verify_row_count": false
}
```

#### `replace_existing`

Controls whether an existing Foreign Table should be replaced.

* `true` — drop and recreate the existing table.
* `false` — skip the existing table.

#### `verify_row_count`

Controls whether the script executes a `SELECT COUNT(*)` after creating the Foreign Table.

* `true` — verify and record the row count.
* `false` — skip row-count verification.

For large production datasets, keeping this disabled avoids unnecessary Parquet reads.

## Directory Structure

The input path should be provided up to the application name.

Example:

```text
/nfs/prddroptim/par/scr_test
```

A single application can contain multiple schema directories:

```text
scr_test/
├── parquet/
│   ├── OPTIM_DETAILS.parquet/
│   └── OPTIM_CUSTOMERS.parquet/
│
├── scr_test_OPTIMDIR/
│   └── parquet/
│       └── OPTIM_CUSTOMERS.parquet/
│
└── scr_test_OPTIMSRC130/
    └── parquet/
        └── OPTIM_ITEMS.parquet/
```

The script automatically discovers the available schema directories and creates the corresponding PostgreSQL schemas and Foreign Tables.

## Usage

Run:

```bash
python3.12 main.py
```

The script provides options for external table creation.

### Option 1 — Create External Tables

This option creates PostgreSQL schemas and Foreign Tables based on the Parquet files found under the supplied application destination path.

The script prompts for the destination path:

Example:

```text
Enter the Destination Path containing parquet files (Path up to application name): /nfs/prddroptim/parq_storage/enwisen
```

The script then discovers the available schemas:

Example:

```text
Discovered 3 schema(s):
  - enwisen
  - enwisen_OPTIMDIR
  - enwisen_OPTIMSRC130
```

It processes each schema and creates the corresponding Foreign Tables.

If a Foreign Table already exists:

* When replace_existing is true, the existing table is dropped and recreated.

* When replace_existing is false, the existing table is skipped.


### Option 2 — Merge Parquet Files

This option allows Parquet files from multiple application or schema paths to be combined into a single PostgreSQL Foreign Table.

The source paths are supplied individually, followed by the target PostgreSQL schema and table name.

The script discovers the actual Parquet files under the supplied paths and creates one Foreign Table referencing all applicable Parquet files.

Example source structure:

```text
application_1/
└── parquet/
    └── OPTIM_ITEMS.parquet/
        ├── part-00000-....parquet
        └── part-00001-....parquet

application_2/
└── parquet/
    └── OPTIM_ITEMS.parquet/
        └── part-00000-....parquet
```

The files can be merged into a single target Foreign Table:

```text
target_schema.OPTIM_ITEMS
```

The generated Foreign Table references the Parquet files from all supplied source paths.

The same replace_existing behavior applies to merged Foreign Tables:

* When replace_existing is true, the existing target table is dropped and recreated.

* When replace_existing is false, the existing target table is skipped.

## Important Notes

* The PostgreSQL Foreign Server configured in `config.json` must already exist.
* The PostgreSQL user running the script must have the required permissions to create schemas and Foreign Tables.
* PostgreSQL must be able to access the referenced Parquet files.
* The Parquet paths supplied to `parquet_fdw` must be accessible from the PostgreSQL server.
* `config.json` should be configured separately for each environment.
